# pcp_mmv

[![CI](https://github.com/sauravsc/pcp_mmv-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/sauravsc/pcp_mmv-rs/actions/workflows/ci.yml)
![MSRV 1.85](https://img.shields.io/badge/MSRV-1.85-blue)
![License: MIT OR Apache-2.0](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue)

Rust bindings to `libpcp_mmv`, the [Performance Co-Pilot](https://pcp.io)
(PCP) library for instrumenting applications with Memory Mapped Value (MMV)
metrics, with safe wrappers.

> **Status: proof of concept.** I wrote this in 2017, during the community
> bonding period of my [GSoC project](https://medium.com/@saurvs/gsoc-2017-introduction-834825fb2aee),
> to compare a Rust-to-C FFI approach with a pure Rust approach
> ([mmv-rs](https://github.com/sauravsc/mmv-rs)) for writing MMV files.
> The project went on to take the pure Rust route, which became
> [**hornet**](https://github.com/performancecopilot/hornet)
> ([crates.io](https://crates.io/crates/hornet)). **For production use, use
> hornet.** This crate is kept building and tested, but is not published to
> crates.io.

## Requirements

- Rust 1.85 or newer.
- 64-bit little-endian Linux (x86_64 and aarch64 are tested in CI).
- `libpcp_mmv` and the PCP headers. On Debian and Ubuntu:

  ```sh
  sudo apt-get install libpcp3-dev libpcp-mmv1-dev
  ```

  To see the metrics in PCP tools such as `pminfo` and `pmrep`, also install
  `pcp` and enable the MMV agent (`cd /var/lib/pcp/pmdas/mmv && sudo ./Install`).

If `libpcp_mmv` is not on the default linker search path, set `PCP_LIB_DIR`
to the directory that contains it.

## Usage

```toml
[dependencies]
pcp_mmv = { git = "https://github.com/sauravsc/pcp_mmv-rs" }
```

```rust
use pcp_mmv::{Flags, Metric, MetricSem, MetricType, Mmv, Units, PM_COUNT_ONE};

let requests = Metric::new(
    "requests", 1, MetricType::U64, MetricSem::Counter,
    Units::new(0, 0, 1, 0, 0, PM_COUNT_ONE), 0,
    "Requests served", "Number of requests served since startup",
);
// Creates $PCP_TMP_DIR/mmv/myapp, usually /var/lib/pcp/tmp/mmv/myapp.
let mmv = Mmv::start("myapp", 1, Flags::empty(), &[requests], &[])?;
let value = mmv.lookup_value("requests", None).expect("metric exists");
value.inc(1.0);
```

The raw bindings generated by `bindgen` are available in `pcp_mmv::sys`.

## Examples

- `acme`: a port of PCP's Acme example,
  [src/pmdas/mmv/acme.c](https://github.com/performancecopilot/pcp/blob/main/src/pmdas/mmv/acme.c).
- `http`: an HTTP server on `127.0.0.1:6767` that counts the GET requests it
  receives.
- `file` (Linux only): counts the `CLOSE_WRITE` notifications that `inotify`
  reports for a file, and publishes a hash of the file's contents. `nano` or
  `echo text > PATH` work best for testing it.

```sh
cargo run --example acme
# In another terminal, with the MMV agent installed:
pminfo -f mmv.acme
# Or dump the file directly (mmvdump ships with the pcp package):
/usr/lib/pcp/pmdas/mmv/mmvdump /var/lib/pcp/tmp/mmv/acme
```

Each example takes an optional argument that makes it stop after a number of
iterations, requests or writes; CI uses this to run them and check their
output with `mmvdump`.

## Bindings

`src/sys.rs` is generated by `bindgen` from `wrapper.h` and is checked in, so
building the crate needs neither `bindgen` nor `libclang`. It is generated on
64-bit little-endian Linux; the crate refuses to build for other targets. To
regenerate it, install `libclang-dev` and `bindgen` (`cargo install
bindgen-cli`), then run `./generate-bindings.sh`. CI regenerates the bindings
on x86_64 and aarch64 and fails if they differ from the checked-in file.
